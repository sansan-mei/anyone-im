# 私密房间密码与图片保留规则

## 私密房间

- 新建房间默认私密，必须设置 6–128 位房间密码。公开房间不要求密码。
- 通过房间 ID 或 `/?room=<room-id>` 链接进入私密房间时输入密码。链接不包含密码，密码请通过其他渠道告知；不会把明文密码保存到浏览器存储、日志或 API 返回值。
- 房主可在房间详情设置或更改密码。服务端只保存 Argon2id 哈希，并限制密码计算并发和加入尝试。密码验证在写入 gate 外运行，加入提交时重新检查已验证哈希，防止改密码竞态。
- 邀请码/邀请链接是可选替代方式，只有房主主动生成才存在，仍遵守 24 小时有效期、撤销及封禁规则。有效邀请可不输密码；持有密码或邀请均不能绕过成员封禁。
- 不存在、未设置密码、缺少/错误密码的私密房间返回相同的通用错误，不暴露私密房间信息。
- 旧私密房间原先没有密码哈希：不会自动设置通用密码或变成公开房间。已有成员继续访问，旧邀请方式仍有效，房主设置新密码后才支持密码入房。更改密码不踢出已有成员，也不自动撤销独立邀请码。

## 图片保留 7 天

- 公开、私密房间相同：从**上传完成并入库的时间**起计算连续 7 天，不按发送、查看或下载时间续期。
- 到达期限即拒绝原图下载及将未发布图片发送为新消息，返回 `410 ATTACHMENT_EXPIRED`。授权检查先执行，过期下载不会读取数据库图片二进制；即使清理 hook 尚未执行，也无法继续访问过期原图。
- 服务启动时和此后每 60 秒触发清理 hook；每次最多处理 100 条到期图片，使用索引筛选，只读取 ID，不读取整个图片内容。并发触发合并，不叠加任务；失败后下次重试，关闭服务会停止计时器并等待在途清理结束。
- 清理将 `Attachment.bytes` 实际置为空字节并记录 `expiredAt`，覆盖已发布、未发布及已删除消息所关联的过期图片。保留少量元数据作为过期占位，防止破坏消息 ID、顺序、图片说明或发送幂等性；不是只在界面隐藏原图。
- 到期图片显示“图片已过期”，文本消息、图片说明及聊天历史继续保留。客户端也按 `expiresAt` 停止显示已到期图片；不会将私密图片加入 service-worker 离线缓存。
- 数据库逻辑删除二进制不代表立刻缩小数据库物理文件，也不能删除用户已下载的副本、历史备份或数据库日志。

## 上线注意

1. 本次只修改代码，**不执行生产数据库更新、图片清理或部署**。
2. MySQL 与 SQLite 均新增可空 `Room.passwordHash`、可空 `Attachment.expiredAt` 以及 `[expiredAt, createdAt]` 索引；部署前需按项目数据库升级流程备份并同步 schema，不能使用 destructive reset / accept-data-loss。
3. 新版本启动后，**既有上传时间超过 7 天的图片也会失效，并被 hook 分批清除二进制**。上线前应明确确认这一数据保留影响，并按需要完成独立备份。
4. 不需要配置 Hermes cron、外部 webhook 或新的公开管理接口；hook 随应用生命周期运行。持续停机期间不运行物理清理，重启后分批补清，下载接口始终校验实际期限。
5. 自动测试在隔离 SQLite / GitHub MySQL 和 Chromium 中验证。生产共享主机不执行本地全量构建/浏览器回归，镜像构建与生产部署继续由用户单独安排。
