# 房间码、短期/长期房间与自动清空

面向“在陌生电脑之间快速传东西”：不靠长链接，只需手输 **6 位房间码 + 密码**。

## 房间码

- 每个房间有一个 6 位数字房间码（可含前导 0），全库唯一；内部 UUID、旧的 `/?room=<id>` 链接和邀请链接继续有效。
- 入口：侧栏「加入房间」→ 输入房间码与密码 →「进入房间」。输入框只保留数字，粘贴 `04 29-17` 会变成 `042917`。
- API：`POST /api/rooms/join-by-code`，body `{ "code": "042917", "password": "..." }`。公开房间可不带密码。
- 房间码不存在、房间已关闭、密码错误或缺失，统一返回 `404 NOT_FOUND`「房间码或密码错误」，不暴露哪些码有效。被房主移出的成员仍返回 403。
- 防猜测（进程内存，重启清零）：
  - 同一会话对同一房间码连续输错 5 次，锁 15 分钟；成功一次即清零。
  - 同一房间码 15 分钟内累计输错 50 次（不分来源），该码锁 15 分钟。
  - 生产环境经 Nginx 反代，后端看到的对端 IP 都是 Nginx，所以按**会话**而不是 IP 计数；全局的码级上限用来兜住换会话撞库。
  - 原有 JOIN 频率限制（默认每会话每分钟 30 次）和 Argon2id 并发上限继续生效。

## 房间类型

创建时选择，网页默认**短期**；API 不传 `lifetime` 时默认 `long`，旧客户端（含移动端）行为不变。

| | 短期 `short` | 长期 `long` |
|---|---|---|
| 关闭时间 | 创建后固定 12 小时，有消息也不续期 | 最后一条消息后 7 天 |
| `RoomSummary.expiresAt` | 创建时间 + 12h | 最后活动 + 7 天（随新消息后移） |

- 大厅 `lobby` 永不关闭，`expiresAt` 为 `null`。
- 到点即不可用：读写消息、上传、成员列表返回 `404 ROOM_CLOSED`，房间从列表消失，房间码入房失败；不依赖清理任务是否已运行。
- 房主可在房间详情「立即销毁房间」（`DELETE /api/rooms/:id`），效果与到期相同。

## 清理任务

- 服务启动时及之后每 60 秒运行，与图片清理一样在写入 gate 内串行执行，每批最多 100 个房间。
- 先给旧房间（`code` 为空）补发房间码，再删除已关闭的房间：消息、图片字节、邀请、成员关系随房间行一起物理删除，房间码随之释放，可再分配给新的空房间。
- 在线成员收到 `room:removed`（`reason: "closed"`），界面提示「房间已关闭，消息已清空」。
- 数据库物理删除不代表立即缩小数据文件，也不影响已有备份和用户已下载的副本。

## 升级与数据影响

- Room 新增列：`code`（可空、唯一）、`lifetime`（默认 `long`）、`expiresAt`（可空）、`activeAt`（默认当前时间），以及 `expiresAt`、`[lifetime, activeAt]` 索引。
- 既有房间按长期处理，`activeAt` 取 schema 同步的时间，所以**老房间从上线起计 7 天**，期间没有新消息才会被关闭清空。
- 上线前备份独立库；schema 同步不使用 reset / force-reset / accept-data-loss。若 `db push` 因新增唯一索引给出数据丢失警告，改用 `prisma migrate diff --from-url ... --to-schema-datamodel ... --script` 生成 SQL，人工确认只有加列和加索引后再执行。
